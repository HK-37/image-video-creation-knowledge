# 知识库规范

## 定位与适用范围

本库是面向 AI 生图、生视频创作的影视专业知识层，采用 `框架V1.1` 的 A（创作决策与视听统筹）、B（视听创作与素材生产）、C（AI 技术控制、后期与交付）三层应用框架。创作职责、制作阶段、可观察创作对象保持关联但不混为同一分类层级；本框架是项目架构选择，不是行业标准部门表。

本规范只约束本项目的条目组织、证据标注和验收表达，不修改 Skill，不把条目自动转成任何模型的默认规则。

## 目录与标识

- `MOC-index.md`：知识地图与建库状态。
- `00-规范/`：`REG-` 规范。
- `20-影视知识/`：`CON-` 概念与应用条目，以 `domain` 标识框架归属。
- `10-标准/`、`30-案例验证/`、`40-证据/`：仅在具备对应材料时建立，分别使用 `STD-`、`CASE-`/`VAL-`、`SRC-`；不建空占位条目。
- 项目原则、来源卡和其他编号必须带命名空间，禁止复用会冲突的 `S1–S10`。
- `id` 与文件名前缀一致；内部关联用 wikilink，链接目标写不带扩展名的文件名。

## 必填元数据与正文

每个文件有 YAML frontmatter，至少包含：

- `title`、`created`（ISO 日期）、`tags`、`source`、`status`、`type`、`id`、`domain`、`evidence-level`、`scope`。
- `source` 使用相对路径或公开 URL；多条来源用分号分隔。论文、教材、官方资料与项目推断分别表述。
- `status` 仅取 `未验证`、`已实测`、`可默认遵守`。外部证据强不等于项目已实测；单案例实测不能自动升级为默认遵守。
- `evidence-level` 沿用 `E1 / E1p / E2 / E3 / E4 / X`，与验证状态独立记录。`E3` 可表示多个独立专业来源支持的实践性命题，不代表因果实验。
- `scope` 标明 `项目内`、`模型限定` 或 `通用`。来源跨域适用但项目尚未实测时，可用 `通用（项目未实测）` 等明确限定，不能省略验证边界。

首批影视知识条目统一使用以下小节：

1. **来源命题**：只写来源实际支持的定义、区分或限定范围内的发现，并公开来源 URL。
2. **项目转译**：面向提示词、参考输入或素材筛选的建议，明确属于项目应用，不冒充来源原文或固定模板。
3. **可观察验收**：分别给出可观察的通过、失败、无法判定依据；不以整体画质、单张最佳帧或工具宣称代替核验。
4. **不适用条件**：含「不能推出」与「结论边界」，写清任务、输入、证据、样本和模型限制。
5. **关联**：用 wikilink 连接相关条目，说明应协同而非互相替代的维度。

## 证据与转译纪律

- 专业事实、行业惯例、项目架构选择、模型能力和项目实测分开写；来源与推断不得混句。
- 一手源可支持其任务、模型、数据和实验范围内的命题，不自动支持任意商业模型的能力或跨模型阈值。
- 官方文档只支持对应产品、平台、版本的功能或推荐方式；教材的章节结构不能单独证明审美因果。
- 项目转译必须能被实际观察或复核；不写只有抽象价值判断、没有检查对象的规则。
- 单案例只能支持带输入和模型限定的观察，不能写成行业规则、普遍成功率或固定提示词公式。
- 不写特定脸型/年龄的统一修图强度、气质到表情动作的一一映射、接触动作的统一公式、跨模型身份阈值、表情/颜色到内心情绪的必然关系。
- 尚未取得的核查不得写成已完成；独立复核与项目验证分别留痕。

## 入库排除项

不复制论文或厂商指南的整段原文，只保留可回查 URL 与简要命题。不入库密钥、令牌、账号、网关鉴权、`state*.json`、原始成片/截图/二进制文件、一次性研究过程记录或本机绝对路径。公开 URL 与库内相对路径可用于回查；案例仅可在未来以结构化卡片引用其结论。

## 首批人物专题范围与状态

B1「人物呈现与视觉身份」分为「身份/外观连续性」和「表演/动作/视线」两条子线。首批共七条：表面修图与几何改变、身份与可变属性、行动目标与身体行为、表情强度与时间过程、姿态/表情/身份分维控制、接触与遮挡、人物整体分维验收。

截至 2026-11-16，上述七条的**人物专题一手源已核**，但**独立人物专题核查未交付**，也尚未完成项目生成验证。因此首批条目均为 `status: 未验证`；「可观察验收」是项目核验方案，不是已取得的实测结果。后续独立复核不得由本库自建行为代替。
